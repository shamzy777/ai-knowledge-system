Q、K、V 各自做什麼？

我們固定更新「it」的表示，逐步分開「如何決定相關性」與「要組合什麼資訊」。

Thecatsatonthematbecauseit更新目標was
Step A｜輸入更新「it」的表示

後面的比較都以這個位置的表示為起點。

Step BQuery（查詢）of「it」

「it」的表示經 learned projection 形成 Query。這是數值比較角色，不是字面上的自然語言問題。

Step C可見位置提供 Keys（鍵）
cat Keymat Keybecause Key…

目標 Query 會和這些 Keys 分別比較。

Step D｜中間結果Query × Keys → relevance scores
Q·KcatQ·KmatQ·Kbecause

這裡只表示會得到比較分數，不虛構實際數值或語意排名。

Step E｜下一步需要的資訊Values（值）承載要被組合的資訊

比較分數之後會成為 weights；weights 決定從各位置的 Value 取多少資訊。

Q + K決定相關程度V承載要組合的資訊

從文字到選出 next token 的因果順序是什麼？

文字 → Tokenization（詞元化）→ 表示 + 位置 → 上下文處理 → scores → Softmax 機率分布 → Sampling（取樣）→ 加入並重複。

Q、K、V 如何分工？

Query 與 Keys 比較；正規化權重決定如何組合 Values。

Softmax 與 Sampling 有什麼差別？

Softmax 建立機率分布；Sampling 從分布中選出一個 token。

token C 能從 `[0.70, 0.29, 0.01]` 中被選到嗎？

可以。它的機率很低，但不是零。

前面的 context token 改變時，後面哪些部分可能改變？

上下文表示、候選 scores、Softmax 機率，以及最後選出的結果都可能改變。

流暢輸出能保證有事實依據嗎？

不能。流暢或高機率的續寫仍可能缺乏依據或不正確。
